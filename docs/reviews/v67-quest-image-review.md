# v67 クエスト画像入力の確認記録

## 実装

登録・編集フォームに画像選択、進行状況、中止、候補選択、元画像の確認を追加。画像選択で既存データを保存せず、候補をフォームへ入力して通常の保存処理を利用する。増分件数を累計に変換し、各段階の追加報酬は維持する。曜日のみの期間は日付が仮入力であることを明示する。

## 確認できた内容

- 添付の943×2048px画像をTesseract.js 7.0.0と日本語データ1.0.0で処理し、2候補を読み取った。
- 共通の画像前処理・行の並べ直し・解析処理をNodeとCanvasのテスト環境でも実行。クエスト1は120／130件・15,700／5,300円、クエスト2は110／120件・11,020／3,740円。欠けている3候補目は除外した。
- 認識結果のバックスラッシュ・「半」の円記号、ピリオドの千区切りを補正。桁の合わない金額、追加記号の不一致、基準のない追加段階は取り込まない。
- 非描画DOM環境で候補選択→自動入力→保存、同一期間の編集、重複期間の拒否、失敗時の手入力保持、フォームを閉じた後の遅延結果の破棄、日付不明時の空欄化を確認した。
- 同一期間の編集で保存済みの売上・稼働日・未知の項目を保持し、進捗の保存値を変更しないことを確認した。
- 構文確認・既存テストを含む164テスト成功。差分の空白検査成功。
- 配信キャッシュ版を67へ統一。通常版だけが画像読み取りモジュールを読み込み、OCR用の外部ファイルは通常起動で取得しない。

## 未確認の範囲

ブラウザーでの画面操作を試みたが、開発サーバー起動時の環境エラーに続き、検証用ページの再読込でCloud browserのURLポリシーに拒否された。拒否後の回避操作は行っていない。

非描画DOM検証は実画面操作の代わりにはならない。以下は成功扱いにしない。

- ブラウザー上での画像選択ダイアログ→OCRの配信ファイル取得→候補選択→保存の一連の操作。
- 幅320／393／430〜440px、画面高とセーフエリアを含む見切れ・重なりの目視確認。
- 実機のiOS Safari・PWAでの動作、更新後の画面復帰、操作回帰。

タイマーと集計の処理は変更していない。通常版・コンパクト版の配信URLだけを新しいキャッシュ版へ更新した。
