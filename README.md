# Uber配達進捗

Uber Eats 配達中に、目標件数に対して今の進捗が足りているかを確認するための小さな Web アプリです。

GitHub Pages で公開し、スマホのホーム画面に追加してアプリのように使う想定です。

## アプリ概要

- 目標件数、完了件数、残り稼働時間から、残り何件必要かを表示します。
- 終了上限を設定していない場合は、12時間制限を基準に進捗を表示します。
- 終了上限を設定した場合は、12時間制限の残り時間と終了上限までの時間を比較し、短い方を基準に表示します。
- 残り時間カウントを ON にすると、移動・停車にかかわらず残り時間を連続で減らせます。
- 残り時間カウントのON/OFFは、メイン画面下部の固定操作エリアから常に切り替えられます。
- 残り稼働時間は設定画面の時間・分プルダウンに加え、メイン画面の`−1分`・`＋1分`で細かく補正できます。長押し中は連続して変更できます。
- 小カードは3枚・4枚（2×2）・6枚（3×2）から表示枚数を選び、表示内容も変更できます。
- 画面右上の設定ボタンから、進捗条件と小カード設定をいつでも開けます。
- 小カードは設定から並べ替えモードを開始し、ドラッグして順番を変更できます。
- 小カードで同じ種類を選ぶと元のカードと入れ替わり、重複表示を防ぎます。
- 実績ペースを小カードに表示でき、目標ペースはメインカード内に固定表示します。
- 目標達成後は「今日のまとめ」に、完了件数・稼働時間・平均ペース・1時間あたり件数を表示します。
- 通常版・コンパクト版のどちらで目標を達成しても、残り時間カウントをその時点で停止します。
- コンパクト版で変更した目標・完了件数・残り時間は、開いている通常版や画面復帰時にも同期します。
- 時間OFFへ切り替えると休憩を自動開始し、時間ONへ戻すと自動終了します。休憩専用ボタンはありません。
- 稼働計測内の休憩時間は`修正`から時・分を手動で合わせられます。休憩中に修正しても、その後の休憩計測は継続します。
- 他社稼働ボタンは時間ON中だけ操作できます。
- 他社稼働中も残り時間は通常どおり減り、履歴ではUber稼働時間と分けて記録します。

## 基本の使い方

1. 目標件数を設定します。
2. 完了件数を現在の配達完了数に合わせます。
3. 残り稼働時間を設定します。
4. 必要なら終了上限を設定します。
5. 配達が完了したらメインカードの `＋`、取り消す場合は `−` を押します。タップでは1件、長押し中は連続して変更できます。別ページのコンパクト版は従来どおり `＋1件`・`−1件` です。

目標件数、完了件数、残り稼働時間、終了上限、カード表示は、画面右上の歯車ボタンから設定します。
終了上限は、時刻選択後に設定画面を`完了`・`×`・背景タップ・下スワイプのどれで閉じても保存され、すぐに進捗計算へ反映されます。

## 画面の明るさと表示

右上の設定 → **画面の明るさ**で選びます。

- **自動**：端末の時刻でライト／ダークを切り替えます。初期設定は06:00にライト、18:00にダークです。開始時刻はそれぞれ変更できます。
- **ライト／ダーク**：時刻に関係なく選んだ表示で固定します。
- アプリを開き直したときや画面に戻ったときも、現在の時刻・設定を反映します。位置情報は使いません。
- 配色設定は配達記録とは別に保存され、テーマ変更でタイマーや履歴を変更しません。通常版と別ページのコンパクト版で共有します。

通常版はメインカードに完了件数と件数操作をまとめ、残り時間・1分補正・他社稼働・時間ON/OFFを下部に固定しています。開始時刻の編集と稼働終了は小カードの下、詳細な稼働内訳・休憩時間の修正・履歴は「稼働の内訳・履歴」から開けます。

トップ左と下部の表示は、緑の **稼働中（時間ON）**、オレンジの **休憩中（時間OFF）** でそろえています。下部ボタンは現在の状態を大きく表示し、その下に「タップで休憩」「タップで再開」を添えます。稼働開始前は「開始前」、稼働終了後は「稼働終了」です。他社稼働中はトップ左にその内訳を表示します。移動・停車や案件の有無による自動切替は行いません。

小カードは2段分が下部の固定操作エリアに隠れないよう、画面の高さに応じて上部の余白とカードの高さを自動調整します。非常に高さの低い画面や文字を拡大した場合は、上部の進捗・案件目安だけをスクロールして確認できます。カードの表示枚数・内容・並び順は維持します。並べ替え中はこの上部の高さ制限を解除します。

4枚表示の標準は実績ペース・必要ペース・終了予測・稼働率です。3枚・6枚表示、内容選択、並べ替えは引き続き利用できます。以前の標準配置のみ新配置へ更新し、個別に選んだカード構成は保持します。稼働率と経過時間は、従来の稼働計測と同じ休憩除外後の数値です。

## 入力項目の意味

### 目標件数

その日の目標配達件数です。

### 完了件数

すでに完了した配達件数です。

### 残り稼働時間

12時間制限のうち、あと何時間稼働できるかの目安です。

大きく合わせる場合は設定画面の時間・分プルダウンを使い、Uber Eats 配達アプリとの数分のずれはメイン画面の残り時間カウント内にある`−1分`・`＋1分`で微調整できます。タップでは1分、長押し中は連続して変更されます。残り時間カウント中に補正しても、カウントはそのまま継続します。

### 終了上限

「今日は何時までに終わりたいか」を入れる任意項目です。

- 終了上限なし: 12時間制限を基準に計算します。
- 終了上限あり: 12時間制限の残り時間と終了上限までの時間の短い方を有効残り時間として計算します。
- 現在時刻より前の時刻を入れた場合、6時間以内の過去時刻は「今日の上限を超過済み」、6時間より前なら翌日の終了上限として扱います。例: 朝10時に `08:00` を設定すると上限超過、夜に `01:00` を設定すると `明日01:00上限` になります。

## 12時間制限との関係

このアプリは、12時間制限を固定の上限として扱います。

終了上限を設定していない場合は、従来通り12時間制限基準で表示します。

終了上限を設定した場合は、12時間制限の残り時間と終了上限までの時間を比較し、短い方を有効残り時間として計算します。

- 終了上限の方が短い場合は、終了上限基準で表示します。
- 12時間制限の方が短い場合は、12時間制限基準で表示します。
- 終了上限が12時間制限より後の場合、終了上限は補助情報として表示し、主計算には使いません。

現ペースで有効残り時間を超える見込みがある場合、終了予測には上限時刻を表示し、補足に `上限到達見込み` と表示します。

## 残り時間カウント

残り時間カウントは、Uber側の時計に手動で合わせるための補助機能です。

- Uber側の残り時間が進んでいる間は ON。
- Uber側の残り時間が止まっている時と休憩中は OFF。
- ON中は移動・停車にかかわらず残り稼働時間が連続で減ります。
- 稼働開始後に時間OFFへ切り替えると休憩を自動開始し、時間ONへ戻すと休憩を自動終了します。
- 稼働開始前と稼働終了後の時間OFFは休憩に加算しません。
- 他社稼働ボタンは時間ON中だけ操作できます。他社稼働は時間ON中の稼働区分であり、残り時間を止めません。
- 他社稼働中に時間OFFへ切り替えると、他社稼働を自動終了して休憩を開始します。時間ONへ戻しても他社稼働は自動再開しません。
- 案件の有無や端末の移動状態は自動判定せず、位置情報も使用しません。
- 内部では秒単位で計算し、画面には分単位で表示します。
- 手動で残り時間を変更すると、その値を基準に再計算します。
- `12時間 − 現在の残り時間`から開始前の消費分を除いた値を今回の稼働合計として計算し、画面ではその内訳を`Uber稼働`と`他社稼働`に分けて表示します。実績ペース・今日のまとめ・履歴も同じ稼働時間を使います。
- 残り時間の補正などで稼働合計が休憩除外後の経過を上回った場合は、残り時間を正本として開始時刻を必要分だけ前へ自動調整します。開始時刻を自動で後ろへは動かしません。
- 開始時刻を手修正した場合は、その入力を優先します。Uber側に合わせた残り時間は変えず、今回の稼働時間を再計算します。遅い時刻へ変更した後に元へ戻した場合も、稼働時間を再計算して戻します。
- 手修正した休憩がある場合も、開始時刻を変えた後の時間枠に収まるよう集計します。元の休憩合計を保持するため、開始時刻を前へ戻したときに再計算できます。
- 実稼働率は稼働合計を休憩除外後の経過時間で割って計算します。残り時間や休憩時間を補正した場合も、その値を使って再計算します。
- 稼働終了時の履歴には、Uber稼働時間・他社稼働時間・終了時の状態を保存します。
- 旧版でUber・他社の稼働合計より経過が短く保存された履歴も、表示時に開始時刻を必要分だけ前へ補正して整合させます。
- 最近の履歴は`修正`から終了日時を直せます。変更後は経過時間と実稼働率を自動で再計算し、件数・稼働時間・休憩時間は元の記録を維持します。
- `使い切り`には、現在から連続でカウントした場合に残り時間が0になる時刻を表示します。ON中は時刻が固定され、OFF中は時間の経過に合わせて後ろへ移動します。
- ON/OFFボタンは下部の固定操作エリアに表示され、メイン画面から操作できます。

## 遅れ時の復帰目安

余裕がある場合は、従来通りシングル・ダブルで受けられる時間の目安を表示します。

遅れている場合は、1件10分ペースを基準に、シングルならあと何件、ダブルならあと何組で予定へ戻れるかの目安を表示します。ダブル1組は20分（平均10分/件）として扱います。

目標ペースが10分/件以下の場合は、10分/件では遅れを回復できない旨を表示します。

遅れは表示上18分まで橙、19分から赤で表示します。

## ホーム画面に追加して使う

スマホのブラウザで GitHub Pages の公開URLを開き、iPhone なら Safari の共有メニューから「ホーム画面に追加」して使う想定です。

PWA表示、スマホ表示、小さめiPhone向けの表示調整を入れています。

## 注意点

- 表示される終了予測や必要ペースは、スマホの現在時刻を使った目安です。
- localStorage に入力値、終了上限、カード設定、残り時間カウント状態を保存します。
- 端末やブラウザの localStorage を削除すると、保存内容も消えます。
- リセットすると、完了件数、残り稼働時間、終了上限、当日の休憩・他社稼働記録が初期状態に戻ります。

## 開発メモ

アプリアイコンは、iPhone用の `apple-touch-icon.png`（180px）と、PWA用の192px・512px画像、ブラウザ用の32px画像をサイズ別に用意しています。

アプリはビルド不要の静的PWAです。HTML、CSS、共通計算、通常版、コンパクト版、稼働計測を分離しています。

```sh
npm run verify
```

画面操作の確認用にViteの開発サーバーと`dev/preview.html`を用意しています。320・393・440px幅、複数の画面高、通常版とコンパクト版の並列表示を選べます。導入・起動方法は保守手順を参照してください。配信時のビルドは引き続き不要です。

仕様と保守手順は次を参照してください。

- [`docs/SPECIFICATION.md`](docs/SPECIFICATION.md): 計算・時計・保存互換の仕様
- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md): ファイル構成と責務
- [`docs/MAINTENANCE.md`](docs/MAINTENANCE.md): 変更・検証・配信手順
