# 配達アプリ仕様

この文書は、保守時に守るべき現在の動作をまとめたものです。利用者向けの説明は `README.md` を参照してください。

## 目的と前提

- Uber Eats の12時間制限を720分の固定枠として扱う。
- 目標件数、完了件数、残り稼働時間から進捗・必要ペース・終了予測を算出する。
- 通常版とコンパクト版は同じ保存データを共有する。
- 位置情報や案件状態の自動判定は行わない。
- 内部計算はミリ秒単位、利用者向け表示は分単位とする。

## 進捗計算

記号を次のように定義する。

- `T`: 目標件数（最低1件）
- `D`: 完了件数（最低0件）
- `R`: 12時間枠の現在残り時間（分）
- `E`: 終了上限を反映した有効残り時間（分）
- `L = max(T - D, 0)`: 残り件数
- `U = max(720 - R, 0)`: 使用済み時間
- `A`: 今回の稼働時間（`U`から開始前の消費分を除外。未開始時は従来どおり`U`）

主な計算式は次のとおり。

- 目標ペース: `(U + E) / T`
- 残り必要時間: `L × 目標ペース`
- 余裕・遅れ: `E - 残り必要時間`
- 必要ペース: `E / L`（目標達成時は0）
- 実績ペース: `A / D`（実績不足時は未計測）。今日のまとめと履歴も同じ稼働時間を使う。
- 終了予測: `実績ペース × L`を現在時刻に加算し、従来の上限表示を適用する。
- 上限まで走ると: `D + E / 実績ペース`。開始前の消費分を完了件数として加算しない。
- 完了率: `D / T × 100`（表示上は0〜100%）

遅れ表示は18分まで橙、19分から赤とする。目標達成時は常に達成色とする。

## 終了上限

- 未設定時は残り稼働時間をそのまま使う。
- 設定時は、残り稼働時間と終了上限までの時間の短い方を有効残り時間にする。
- 現在より前の時刻が6時間以内なら「本日の上限超過」とする。
- 現在より6時間を超えて前の時刻なら翌日の時刻として扱う。

## 残り時間カウント

- 時間ON中は、画面表示や端末の移動状態にかかわらず連続して残り時間を減らす。
- 時間OFF中は残り時間を減らさない。
- 稼働開始後のOFFは休憩開始、次のONは休憩終了として記録する。
- 「一時停止」は残り時間のみを止め、休憩区間を開始しない。休憩を除く経過時間は進む。「再開」は停止した残り時間から計測し、停止中の時間を後から消費しない。
- 一時停止中の「休憩する」は、その時点から通常の休憩を開始する。開始前・休憩中・稼働終了後は一時停止ボタンを無効にする。
- 一時停止前に他社稼働ONだった場合、区間を閉じ、再開時に他社稼働を復元する。一時停止中は他社稼働にも加算しない。休憩への切り替え・終了・セッションのリセットでは復元予定を解除する。
- 一時停止状態は再読み込み・画面復帰・通常版とコンパクト版の同期で維持する。終了上限は実時刻を基準にするため一時停止中も進む。
- 残り時間の手動変更は、現在値を新しい基準にして計測を継続する。
- 残り時間から算出した総稼働が休憩除外後の経過を上回る場合は、残り時間を正本として開始時刻を必要分だけ前へ補正する。開始時刻を自動で後ろへは動かさない。
- 初回の時間ON時点ですでに消費されていた12時間枠はセッション開始前の基準値として保持し、当セッションの稼働時間へ含めない。
- 開始時刻の手修正時は入力を新たな基準とし、開始前の消費分を`max(使用済み時間 - 修正後の休憩除外経過, 0)`へ再計算する。前後どちらへ修正しても増減でき、残り時間は変更しない。
- 目標達成または残り時間0でカウントを停止し、他社稼働中ならその区間も閉じる。
- 端末時刻が巻き戻っても、保存済みアンカーより前へ更新時刻を戻さない。

## 稼働・休憩・他社稼働

- 稼働時間の正本は `720分 - 残り時間 - 開始前の消費分`（最低0）とする。進捗の余裕・遅れと目標ペースは従来の12時間枠の計算を維持する。
- 他社稼働は時間ON中のみ開始でき、残り時間の減少は止めない。
- Uber稼働は総稼働時間から他社稼働時間を差し引く。
- 常に `Uber稼働 + 他社稼働 <= 休憩除外後の経過` を満たす。
- 休憩区間と他社稼働区間は、重複する区間を統合して集計する。
- 開始時刻の手修正で、手入力の休憩合計が修正後の時間枠に収まらない場合は、その超過分を今回の集計から除外する。元の合計と区間は保持し、開始時刻を前へ戻せば再計算して復元する。除外量は編集時に固定し、時間ONへ戻した後に休憩が増加したり開始時刻が戻ったりしない。
- 稼働終了後は時計と集計値を固定し、履歴へ一度だけ保存する。
- 旧版で稼働合計より経過が短く保存された履歴は、読み込み時に開始時刻を必要分だけ前へ補正し、経過と実稼働率を整合させる。
- 履歴の終了日時を直した場合は、経過時間と実稼働率のみ再計算する。
- 履歴の終了日時が入力欄の表示から未変更なら、元の秒を保持して編集を閉じる。実際に変更した日時には従来の検証を適用する。

## 表示・操作の互換要件

- アプリ名、アイコン、配色、カード構成、モバイルレイアウトを意図せず変更しない。
- 通常版は小カード3枚・4枚・6枚を選択でき、順番と内容を保存する。
- 通常版とコンパクト版は `storage` イベントと画面復帰時に同期する。
- VoiceOver向けのラベル、ダイアログのフォーカス復帰、設定シートのスワイプ操作を維持する。
- 320〜440px幅で残り時間表示と主要操作が欠けないこと。
- メインカードの完了件数・増減ボタン・達成率と下部の目標ペースは、カード内のスクロール領域の外に表示する。スクロール対象はペース・案件時間の目安だけとし、件数ラベルが途中で切れない構造にする。画面高が不足する場合も件数ヘッダー・目標ペース・小カードの高さを確保し、クエスト要約の表示・折り返し時には利用可能な高さを再計算する。最低限の高さも収まらない画面はページ全体をスクロールでき、固定操作エリアの高さ分の下余白を維持する。
- 440px以下ではクエストの開始・終了の日付／時刻を縦1列に配置し、iOSの日付入力の最小幅が隣の時刻欄へはみ出さないようにする。

## 保存データの互換要件

### v67 クエスト画像入力

- 通常版の登録・編集フォームで、Uberのクエスト選択画面の画像を読み取る。複数候補は利用者が選択し、単一候補はフォームへ自動入力する。保存は既存フォームの「保存する」で行う。
- 各段階の「＋n回」を必要累計件数に変換し、「＋金額」は追加報酬として保持する。既存の集計・保存形式に合わせ、画像解析で配達件数記録や時計を更新しない。
- 選択期限の日時と開催期間を区別する。曜日＋時刻の期間は日本時間で仮の日付に変換し、その旨を表示する。「次のクエスト」は将来の開始日、通常画面は現在の期間または次の期間を使う。撮影日や対象週は確定しないため日付を編集可能とする。
- 読み取れない期間は新規フォームの日時を空欄にする。未来の期間は初期累計と今日分に0を入力し、開始済みの新規・期間変更では公式件数の入力を求める。同一期間の編集は件数補正・売上・稼働日を保持する。
- 不正な金額桁区切り、増分の不一致、件数のみの途中段階などは該当候補ごと除外する。候補をまたいで段階や報酬を補完しない。
- Tesseract.js／Core 7.0.0と日本語データ1.0.0を固定し、画像選択時のみ読み込む。画像はCanvas・Web Workerで端末内処理し、APIへ送信しない。既存の手入力・記録閲覧はOCRの通信成功を要件としない。
- PNG／JPEG／WebP、20MB上限、処理用Canvasは最大600万画素。90秒の制限と中止ボタンを設ける。閉じたフォームへの遅延した結果は破棄する。

### クエストの集計・保存（v64以降）

- v71以降は起動時に開催中の登録済みクエストを自動表示する。開催中がなければ最も近い開始前の期間、すべて終了済みなら最新の期間を表示する。以前の`selectedId`に表示を固定しない。次の開始・終了日時と画面復帰時に再判定し、03:59:59.999まで旧期間、04:00から新期間へ切り替える。過去期間の手動閲覧は次の期間変化またはクエストタブを開き直すまで維持する。
- 切替は表示のみで、クエスト・件数・補正・売上・進捗時計の保存形式や内容を変更しない。次期間が未登録なら登録を案内し、過去の条件を自動複製しない。設定・売上・件数補正の入力中は保存または閉じるまで切替を待ち、操作は画面に表示した期間IDへ反映する。
- 通常版に「進捗」「クエスト」タブを設ける。タブ切替は時計を停止・再開しない。期間中のクエストは進捗画面とコンパクト版にも累計を表示する。
- 新しい独立キー `ubereatsProgressQuestV1` に段階設定、稼働日、件数記録、補正、日別配達売上を保存する。従来の進捗・時計・履歴の形式は変更しない。
- 保存上の期間は日本時間で開始を含み、終了を含まない。画面・入力欄は最後に含まれる分を「〜まで」と表示し、04:00境界は03:59まで（03:59:59.999を含む）とする。入力した終了分の次の分を保存上の終了とし、再編集で日時欄を変えなければ既存のミリ秒・件数・売上・稼働日を保持する。既存保存値の移行はしない。
- ひな形は月〜木／金〜日で、開始04:00・終了03:59までを入力する。「今日」の区切りはクエスト開始時刻とし、画面に明示する。OCRの04:00終了は入力時に03:59までへ変換し、画像自体が03:59表記の場合は重ねて1分引かない。
- 1〜5段階を登録できる。必要件数は累計で昇順、報酬は各段階の追加額。重複期間は受け付けない。期間を修正する場合は公式の累計・今日分を再入力して合わせる。
- 初回は既存の進捗件数を無条件に取り込まず、公式の累計・今日分を登録する。以後、通常版・コンパクト版の明示的な件数変更のみを記録する。タイマー・カード設定・再読込・同期受信で重ねて加算しない。
- 日次リセットは記録を保持して新しい件数基準を開始する。減算は現在の基準内で直近の配達を元の日時から取り消す。旧版との不一致を見つけた場合は累計を保持し、公式件数の確認を促す。
- 日々の目安は `ceil((目標 − 期間累計 + 今日の件数) / 残り稼働日数)`。休日を除外し、今日の配達ごとに目安が上がらない。反映する進捗目標は `現在の完了件数 + 今日の追加必要件数` とし、同日リセットにも対応する。両画面の目標は1〜80件。
- 見込み単価は狙う段階までの報酬合計÷必要件数。より上の段階が達成済みならそこまで含める。配分件数には上限を設け、日別の配分は累計円額の差分で丸める。達成済み報酬を見込み売上へ再加算しない。
- 締切後は記録上の達成報酬だけを期間全件に配分する。未達成の見込みは取り除く。実際の支払い確定は公式アプリで確認する。
- 過去件数を累計だけで取り込んだとき、複数の過去日の配分は未確認として表示する。日別売上に架空の配分額を表示しない。登録後の配達は日時を記録する。
- 稼働履歴は集計元にしない。履歴の保存・削除・日時編集ではクエスト件数を変更しない。件数補正を開いたまま別期間へ切り替えると補正欄を閉じる。

### v63 稼働状態の表示

- 通常版のトップ左と下部操作エリアは、現在の状態を同じ配色で表示する。稼働中は緑、休憩中はオレンジ、開始前・稼働終了後は中立色とする。
- 「稼働中」「休憩中」を主表示にし、時間ON／OFFを補足する。トップ左の表示には濃いバッジと淡い背景を用い、下部ボタンにはタップ後の操作も小さく表示する。
- 他社稼働中も緑の「稼働中」を維持し、トップ左に「時間ON・他社稼働」を添える。
- 状態表示は時計の既存状態から導出する。位置情報・案件獲得状態・停車の自動判定は追加しない。
- `endedFromState`を含む保存済みデータの項目・値は変更しない。状態表示の読み上げは状態が変わったときだけ更新する。

### v61 表示テーマとUI

- ライトはミントを基調、ダークはチャコールを基調とし、指標の数式・遅れの閾値は変更しない。
- テーマは`auto`・`light`・`dark`。自動の初期時刻は端末の06:00／18:00で、開始時刻を変更できる。位置情報や日出・日没APIは使わない。
- ライト開始時刻を含み、ダーク開始時刻を含まない区間をライトにする。日跨ぎの時刻設定も扱う。同一時刻は受け付けない。
- 配色変更は新しい独立キー`ubereatsProgressAppearanceV1`にだけ保存し、既存の進捗・稼働時計・履歴を書き換えない。
- 初回描画前、時刻境界、画面復帰、別タブの設定変更でテーマを更新する。非表示中はテーマ用のタイマーを止める。
- 通常版の4枚標準は実績ペース・必要ペース・終了予測・稼働率。従来の標準配置のみ移行し、個別構成は保持する。既存8指標も選択肢から削除しない。
- 稼働率・経過時間の小カードは`session-engine.js`の読み取り専用表示値を利用し、計算を複製しない。
- 下部操作エリアの実測高さを本文の余白へ反映する。バイクは1台と2台で同じSVG・同じ1台あたりの寸法を用いる。

次のキー名は公開済みの永続化契約であり、移行処理なしに変更しない。

| 用途 | localStorageキー |
| --- | --- |
| 進捗・表示設定 | `ubereatsProgressFixed12Data` |
| 旧時計との互換 | `ubereatsProgressClockState` |
| 稼働時計 | `ubereatsProgressMovementClockV1` |
| 稼働履歴 | `ubereatsProgressWorkHistoryV1` |
| ペース表示 | `ubereatsProgressPaceDisplayMode:` 接頭辞 |

既存オブジェクトへ項目を追加する場合も、未知の項目を消さず、旧形式を読み込める状態を維持する。

v66では稼働時計の既存キーに`paused`（一時停止）と`resumeOtherCompany`（再開時に他社稼働を復元）を追加する。未保存の場合はどちらもfalseとし、既存のOFF・休憩データの扱いは維持する。稼働終了・セッションのリセット・休憩開始時は両フラグを解除する。コンパクト版の稼働中リセットは従来どおり件数と残り時間のみを戻し、一時停止状態を維持する。

v60では稼働時計に`legacyBreakExcludedMs`（手修正した休憩のうち、開始修正により今回の集計から除外した量）を追加する。旧データで未保存の場合は0として読み込み、休憩合計の再入力とセッションのリセットで0に戻す。`legacyBreakMs`と`breakSegments`の既存形式は維持する。

### v68 進行中クエストの画像入力

- 「クエストの進捗」では最初のn/m回を累計n件・第1段階m件として読む。案内文の残り件数は目標として取り込まず、読めた場合はnとの整合を確認する。追加報酬に＋のあるロック段階は件数に＋がなくても増分とする。
- 月日・曜日・時刻がある期間を優先し、存在しない日付や曜日不一致を拒否する。年省略時は現在の前年〜翌年から最も近い整合する年を仮定し、その旨を表示する。
- 累計はフォームへ入力する。今日分は累計0以外では空欄にし、新規・同一期間編集とも入力を必須にする。保存時のみ既存の件数補正処理を通す。売上・稼働日・進捗画面の件数を変更しない。
- 複数の進捗分数が写る場合は期間累計を確定できないため取り込まない。
