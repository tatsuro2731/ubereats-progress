# v96 押した感（振動）

## 依頼

「件数カウントしたら押した感みたいなコンコンみたいな背面にくる機能付けれる？」

## 調べたこと

- iPhoneのブラウザー（ホーム画面に追加したアプリを含む）にVibration APIは無い。
- ページから出せる触覚は、標準スイッチ（`<input type="checkbox" switch>`、Safari 17.4から。触覚はiOS 18.0から）を切り替えたときのシステムの「コツ」だけ。
- 以前は`label.click()`でスクリプトから鳴らせたが、iOS 26.5で塞がれた。いまは本人のタップがスイッチのラベルに届いたときだけ鳴る（1タップ1回）。
- 出典：ios-haptics README（unpkg.com/ios-haptics@3.1.1/README.md）、同 PR #13（github.com/tijnjh/ios-haptics/pull/13）、WebKit Bug 285120。

## 変更

- `src/haptics.js`を追加。`＋`は2回、`−`は1回の振動を出す（Android）。iPhoneでは透明なラベルで包んだスイッチを`＋`・`−`に重ね、タップをそこで受けてからボタンへ渡す。
- 設定に「押した感（振動）」ON／OFFを追加（初期値ON）。新キー`ubereatsProgressHapticsV1`。既存キーと形式は変更なし。
- 通常版・コンパクト版の両方で読み込む。キャッシュ版番号を96に揃えた。
- 設定「見た目のスタイル」の説明文が古いまま（「質感だけを切り替えます」）だったので直した。

## 差分レビュー

- 件数の計算・保存・時計には触れていない。`main-app.js`・`compact-app.js`・`quest-ui.js`の差分は版番号だけ。
- 通常版の長押し処理は、ポインター操作のあとに届くクリックを捨てる。ラベルは受けたクリックの伝播を止め、ボタンへ新しいクリックを渡す。通常版では捨てられ（件数はポインター操作で1回だけ増える）、コンパクト版ではそれで数える。
- スイッチ自身のクリック・input・changeはボタンへ伝えない。伝わるとコンパクト版で二重に数える。
- ラベルはボタンの枠線の上まで覆う（`inset: -1px`）。枠線だけ外れると、そこを押したときに鳴らない。
- ラベルとスイッチは`aria-hidden`、フォーカス対象外。キーボードと読み上げはこれまでどおりボタンを直接操作する。

## 確認

- `npm run verify`（278件）、`git diff --check`。
- Chrome（Playwright、タッチ入力、393×852、リッチ／クラシック）で実際にタップ。
  - iPhone相当（Vibration APIを外した状態）：ラベルが`＋`・`−`の全面を覆いタップを受けること。`＋`3回で+3、`−`1回で−1（二重計上なし）。スイッチがタップごとに切り替わること。1秒の長押しで連続加算し、離したあと増えないこと。Enterキーで+1。残り時間の−1分は従来どおり。
  - 設定でOFF → ラベルが外れボタンが直接タップを受け、件数は従来どおり。コンパクト版も追従。ONに戻すと両画面で復帰。再読み込み後も保持。
  - コンパクト版：`＋`3回・`−`1回で+2。通常版へ同期。
  - Android相当（Vibration APIを記録用に差し替え）：`＋`で`[25, 60, 25]`、`−`で`[25]`、OFFで呼ばれないこと。ラベルは作られないこと。
- 320×568・393×852・440×956、通常版／コンパクト版、リッチ／クラシックの12通りで、主要要素の位置と大きさがv95と一致。
- 既存の回帰確認（主要操作3幅、スタイル切替と同期、動きの演出と「視差効果を減らす」、詰め方の段階）に変化なし。ページエラーなし。

## 未確認

- **実機のiPhoneで本当に振動するか。** ここにはiPhoneもWebKitも無く、確認できたのは「タップがラベルに届き、スイッチが切り替わり、件数が1回だけ増える」ところまで。振動そのものはiOSが出すもので、Chromeでは再現できない。
- 特に通常版は、ボタンが`pointerdown`で既定動作を止めている。iOSでそのあともクリックがラベルへ届くかは実機で見る必要がある。コンパクト版は通常のクリックなので、通常版だけ鳴らない場合はここが原因になる。
- 実機のAndroid。
