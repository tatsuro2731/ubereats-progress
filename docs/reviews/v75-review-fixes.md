# v75 レビュー指摘の修正

## 依頼と修正

1. ＋／−ボタン（完了件数・残り時間）のタップ判定を、`click.detail` が0かどうかではなく「ポインター操作で処理済みか」で判定する。`detail` の値はブラウザーごとに異なり、Chromiumのタッチ操作では1回のタップで2件増えた。キーボード・支援技術からの操作は従来どおり1回ずつ反映する。
2. 設定に「データのバックアップ」を追加。`ubereatsProgress` で始まる全キーをそのままJSONに書き出し、読み込み時は確認のうえ置き換える。書き込みに失敗した場合は元の値へ戻す。別アプリのファイル、未対応形式、空データは書き込む前に拒否する。
3. 時計のlocalStorage書き込み（通常版・コンパクト版・編集ダイアログ・旧時計）を `storeItems` に統一。容量不足などで失敗しても例外で処理を止めず、関連キーを元に戻し、通知は失敗が続く間1回だけ。クエスト保存の失敗通知も、ブラウザー固有の英語メッセージではなく日本語で表示する。
4. Service Workerの照合を変更。画面遷移はクエリを無視（`./`、`./?v=10`、`index.html` をオフラインで開ける）、それ以外は `?v=` まで完全一致し、一致しない場合はネットワーク、オフライン時だけクエリを無視した代替を返す。外部CDNへの要求には介入しない。アイコン・manifestをHTMLの参照URLどおりに事前キャッシュする。
5. `main-app.js` の旧時計処理のうち、起動後に必ず置き換わり一度も実行されないもの（旧リセット処理、旧ON/OFF割り当て、旧 `adjustRemain`・`toggleClock` 本体）を削除。旧データの移行に使う `remain`・`loadClock` などは保存互換のため残し、役割をコメントと `ARCHITECTURE.md` に記載した。

## 保存・影響範囲

- 既存のlocalStorageキーと保存形式は変更しない。バックアップは値を文字列のまま複製する。
- 12時間カウント、休憩、他社稼働、履歴、クエストの計算は変更しない。
- HTML参照、Service Worker登録、キャッシュ名・アセット、OCRの診断表示、`quest-image.js` の読込URLをv75に揃えた。

## 実施した確認

- `npm run verify`: 構文確認と220件の自動テストが成功（追加: `storeItems` のロールバックと通知1回、バックアップの往復・失敗時ロールバック・不正ファイル拒否、Service Workerの事前キャッシュ対象）。
- `git diff --check`: 成功。
- Chromium（Playwright、タッチ操作の再現）で実画面を操作:
  - ＋を3回タップで3件、−で1件減、長押しで連続増加、キーボードのEnterで1件増。−1分タップで1分減。
  - 時間ON→稼働中、時間OFF→休憩中。コンパクト版で件数が同期。
  - 書き出したJSONにアプリのキーが入ること、件数を変えた後に読み込むと書き出し時点の件数へ戻ること、別アプリのファイルは拒否され記録が変わらないこと。
  - localStorageの書き込みを失敗させた状態で時間ON中に12秒経過→時計は動き続け、通知は1回、ページエラーなし。
  - 320・393・440px幅で通常版・コンパクト版とも横スクロールなし、設定のバックアップ欄が画面内。ライト・ダーク両方で表示を確認。
  - Service Worker有効化後にオフラインで `./`、`index.html`、`compact.html`、`./?v=10` を開けること。
