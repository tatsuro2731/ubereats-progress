# 保守・リリース手順

## 開発前

1. `docs/SPECIFICATION.md` で対象機能の現行仕様を確認する。
2. 変更によって保存データ、時計、通常版・コンパクト版同期へ影響がないか整理する。
3. 判断で結果が変わる不足情報だけを依頼者へ確認する。
4. バグ修正では、可能なら先に再現テストを追加する。

## 実装中

- 共通計算を画面ファイルへ複製せず、`app-core.js` に置く。
- 表示用の丸め値を、ミリ秒単位の正本へ書き戻さない。
- 保存済みオブジェクトを更新する際は、未知の項目を保持する。
- UI変更は320px、393px、430〜440px幅を考慮する。
- アクセシビリティ用ラベル、キーボード操作、フォーカス復帰を維持する。

## 自動検証

Node.js 20以上で次を実行します。外部パッケージのインストールは不要です。

```sh
npm run verify
```

検証内容は次のとおりです。

- 全JavaScriptの構文確認
- 進捗・終了上限・区間集計の単体テスト
- 通常版とコンパクト版の保存・同期テスト
- 時計、休憩、他社稼働、履歴の状態遷移テスト
- モバイル表示、アクセシビリティ、PWAキャッシュの契約テスト

## 差分レビューと画面操作確認（毎回必須）

2026-09-06のユーザーの継続指示により、アプリ更新のたびに差分レビューと実際のブラウザー画面操作を行います。詳細な完了条件は`AGENTS.md`を参照してください。

差分レビューでは依頼との一致、既存仕様、保存互換、時計と画面間同期への影響を確認します。画面操作はテスト用の状態で行い、実際の稼働記録を変更しません。自動テストやコード確認だけで画面確認を済ませたことにしません。

リリース前に変更対象の操作と主要操作を確認し、次の項目は変更の影響範囲に応じて検証します。問題があれば修正して再確認します。実施できない項目があれば、理由と未確認範囲を報告します。

- 初回表示が「完了0件・残り12時間」になる。
- 時間ONで減少し、OFFで停止する。
- `−1分`・`＋1分`後もON状態と秒精度を保持する。
- OFFで休憩が始まり、ONで終了する。
- 他社稼働はON中だけ切り替えられる。
- 通常版とコンパクト版で目標・件数・残り時間が同期する。
- 目標達成で時計が停止する。
- 設定シートを完了、×、背景、下スワイプの各方法で閉じられる。
- 320〜440px幅で主要情報とボタンが欠けない。
- 小カードの上下2段が固定操作エリアに隠れず、画面高の変化や復帰後も操作できる。
- ホーム画面追加後のPWA更新とオフライン起動ができる。

## 配信

配信ファイルを変更した場合は、必ず次の版番号を揃えます。

- HTML内のCSS・JavaScript URLの `?v=`
- JavaScript内の `sw.js?v=`
- `sw.js` の `CACHE`
- `sw.js` の `ASSETS`

`npm run verify`、`git diff --check`、変更内容の確認を終えてからコミット・pushします。
