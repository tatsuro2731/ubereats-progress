# v77 メインカード内のスクロールの廃止

対象: `tatsuro2731/ubereats-progress`、基準コミット `e08ddf6`（v76）。

## 報告と原因

ピンチアウトすると、メインカードにスクロールバーが出て中身が動き、見切れるという報告（画面収録あり）。

- 収録はiPhone 16 Pro Max相当（440×956、上62px・下34pxのセーフエリア）、ダーク表示、クエスト要約あり、小カード4枚。
- 画面の高さに収まらないとき、`appearance.js` がペース・案件時間の目安（`dashboardOverview`）に高さの上限を付け、カード内だけをスクロールさせていた。この条件では155pxの内容が126pxに制限され、29pxが隠れていた。静止時も一部が切れ、指やピンチの操作で中身だけが動いてスクロールバーが出る。
- 393〜402px幅のiPhoneでクエスト要約がある場合は、44〜50pxまで縮められ、約2/3が隠れていた。
- ピンチで拡大している間、iOSは`innerHeight`に拡大後の見えている高さを返すため、再計算で領域がさらに狭まるおそれがあった。

## 修正

- `dashboardOverview` に高さの上限と内部スクロールを設けない。メインカードの中身だけが動いたり、途中で切れたりしない。
- 詰め方にtightを追加（comfortable→compact→dense→tight）。denseで収まらない場合だけ使い、「目標ペースに対して」を余裕・遅れの値と同じ行に置き、「案件時間の目安」の見出しを省く。値、シングル／ダブルの目安と復帰目安、残り件数と上限までの時間、目標ペースは省かない。
- tightでも収まらない低い画面では、ページ全体のスクロールで下の小カードを表示する。固定操作エリアの高さ分の下余白は従来どおり。
- ピンチで拡大している間（`visualViewport.scale`が1以外）と並べ替え中は詰め方を変えない。倍率が1に戻ると再計算する。
- スクロールしなくなったため、`dashboardOverview` のフォーカス停止（`tabindex`）をなくし、読み上げ名から「スクロールできます」を外した。
- 配信リソースとService Workerの版番号を77に統一。

## 保存・影響範囲

- localStorageのキーと形式、時計、件数、クエスト、カードの構成・内容・並び順は変更しない。詰め方は表示のみ。
- コンパクト版には同じ領域がなく、影響しない。

## 実施した確認

- `npm run verify`: 構文確認と229件の自動テストが成功。`git diff --check` も成功。
- レイアウトの自動テストを新しい動作に合わせて書き換えた。上限を付けない、tightはdenseで収まらないときだけ、収まらなければページのスクロール、ピンチ拡大中と並べ替え中は変えない、クエスト要約の表示切り替えで再計算、の各項目。旧版の `appearance.js` では12件中9件が失敗し、新版で全件成功することを確かめた。
- Chromium（Playwright、タッチ操作）で実画面を操作。Chromiumはセーフエリアを持たないため、iPhoneの値を当てるCSSを加えて再現した。
  - 440×956・クエスト要約・小カード4枚（報告と同じ状態）: v76ではカード上を指でなぞると中身だけが29pxスクロールし、「25分余裕」が切れた。v77ではページ全体が動き、カード内は切れない。2本指で広げる操作ではページが拡大され、詰め方は変わらない。
  - 320×568、375×667、393×852、402×874、430×932、440×956で、クエスト要約あり・なし、小カード3・4・6枚を確認した。全条件でカード内の切れは0、横スクロールなし、エラーなし。
  - 440×956と430×932（4枚）はすべて固定操作エリアの上に収まる。タブの往復や並べ替えの後も同じ。
  - 393・402px幅でクエスト要約ありの場合、下段のカードは35〜83px固定操作エリアの下から始まり、ページのスクロールで表示できる。以前はカードは見えていたが、目安の約2/3が隠れていた。
  - 遅れ（復帰目安）の表示、終了上限の残り時間、目標達成、ライト・ダーク表示を確認した。
  - 件数の＋／−、時間ON／OFF、一時停止、±1分、設定の4通りの閉じ方、並べ替え、再読み込み、コンパクト版との同期、稼働終了の一連の操作は、v76と同じ結果になった。

## 未確認範囲
