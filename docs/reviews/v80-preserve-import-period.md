# v80 画像読み取り前の日時を保持する

基準: `74907eb462d7a0d575c3ab3af300f3200fb39383`（v79）。

## 原因と変更

利用者から「画像を読み込むと時間が空欄になります」「読み込む前は入力されてる」と報告があった。新規登録フォームで画像から期間が読めないと、`applyImageCandidate()`が開始・終了の日付と時刻4欄を明示的に空にしていた。ひな形や手入力の日時も消える直接原因はこの処理である。

- 期間が読めない場合の日時消去を除去した。入力済みの日付・時刻・ひな形はそのまま残す。
- 期間を読み取れず元の日時を保持したことと、Uberの画面との照合が必要なことを表示する。元から空の欄は空のまま。
- 期間を読み取れた場合は従来どおり反映する。03:59と04:00境界の処理、報酬候補・累計件数の反映、保存形式・タイマーは変えない。
- 配信版番号を80に統一した。

## 検証と公開

- `npm run verify`: 全241件成功。
- 実際の配信スクリプトで新規登録・画像取込イベントを実行する回帰テスト4件を追加した。ひな形の日時、手入力の日時と自由設定、一部空欄の保持、読めた期間の上書きと04:00→03:59表示を検証した。追加3件は旧消去処理では失敗する。
- `git diff --check`: 成功。
- 独立レビューで、保存処理・保存形式・タイマーに変更がないことと、読めた期間を反映する従来処理が維持されていることを確認した。
- これらはDOMを模したデータフローの検証であり、実際のブラウザー画面操作とは区別する。

今回の元のUber画像・OCR文字は未提供であるため、期間OCRが失敗した文字の詳細は未確定。ただし入力済み日時を消す経路は現行コードと利用者の説明で特定できる。

実画面の操作確認は前回と同じブラウザー制限で未実施。利用者が2026-10-06に承認した、画面未確認での先行公開による本不具合の修正を継続する。未実施の画面確認を成功扱いしない。
